Motive coding: human validation

Codebook and rules (read once before starting)

Unit. One repository. Code the repository from all the items shown for it together: a code applies if any item states it. Code only from the text shown here. Do not open the repository on GitHub. Do not code a motive that you infer from the action; code it only when the text states it.

Relevance (R). R = 1 if any item discusses the supplier's licence change, a move to, from or alongside the fork (Pekko, OpenSearch), or the choice of supplier version in light of the relicensing. R = 0 otherwise: the project's own LICENSE file, other libraries' licences, or automated bumps that do not mention the licence or the fork.

CodeApply when the text states...
LEGAL_OWNThe licence terms bind the project itself: fees, compliance, commercial use, legal review, incompatibility with the project's own licence or its foundation's policy (for example ASF Category X), or failing licence checks.
LEGAL_USERSDownstream users or customers cannot or will not accept the licence (the licence is given as the users' reason).
LICENCE_UNSPECThe licence change is given as a reason, but the text does not say how it binds (for example "switching to Pekko because Akka is now BSL"). Use only when neither LEGAL_OWN nor LEGAL_USERS applies.
USER_REQUESTSomeone asks the project for a fork variant or fork support. Can be combined with other codes when a motive is also stated.
TRUSTDistrust of the supplier: fear of further restriction, "rug pull", vendor lock-in, preference for foundation or community governance.
AGEINGSecurity fixes, CVEs, end of patches for the open line, bugs fixed only in newer versions.
COMPATCompatibility needs: Scala 3, JDK, a server or another dependency requiring a newer supplier or fork version, or clients that refuse to connect.
COORDWaiting for, or following, other dependencies or the ecosystem (ports not yet available, Play 3, other libraries moved).
COSTEffort, risk or breakage of migrating or upgrading.

Action (one value, R = 1 only). The decision shown by the latest item that states one: SWITCH (replace with the fork), DUAL (publish both), STAY (keep the open line), UPGRADE (take the restricted versions), REMOVE (drop the supplier), DISCUSS (no decision in the items).

Saving. Codes save in this browser as you go. Use Export CSV when you finish, or to back up. To continue on another browser, use Import CSV.
